## Цель

Дешёвая предварительная проверка «адреса точно нет в blacklist», чтобы не
трогать LPM-трию и не брать лок на каждый пакет.

## Зачем

Blacklist lookup в XDP уже LPM, но при росте списка до сотен тысяч записей
память и стоимость lookup растут. Bloom-фильтр даёт negative lookup за один
memory access.

## Non-goals

- Точная проверка без false positive: Bloom только отсеивает, финальное слово за
  картой blacklist.
- Замена существующих карт: фильтр — дополнение.

## Approach

1. Сначала измерить: при каких размерах списка LPM lookup становится узким местом
   (bench + `bpftool map show`).
2. Если выигрыш есть — Bloom в отдельной карте, обновление при ban/unban,
   периодическая пересборка из источника правды.
3. Тесты: false-negative == 0, память в лимитах, поведение при переполнении.

## Критерии приёмки

- [ ] Бенчмарк до/после на списке ≥ 100k.
- [ ] Ноль false negative на property-тестах.
- [ ] Деградация при переполнении описана и безопасна (fail-open к точной карте).
