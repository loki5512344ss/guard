## Цель

Отвечать на «почему этот IP отброшен» и «сколько стоит программа» без побочных эффектов.

## Зачем

Идея ebpfsentinel (AGPL — только идея): тестовый прогон программы
(`BPF_PROG_TEST_RUN`) с маркером в metadata — программа принимает решение как обычно, но не
пишет в карты и счётчики и возвращает запись вердикта. Нужна и для CI, и для оператора.

## Scope

- `rampart-cli explain <ip>[:port]`: вердикт и причина (whitelist, бан, throttle, порт-гейт)
  без изменения состояния.
- Стоимость программы: прогон синтетических пакетов через `test_run`, нс/пакет, с пустыми и
  заполненными картами — метод для [v0.6-hot-path-perf.md](v0.6-hot-path-perf.md).
- Open-loop генератор нагрузки (отправка по сетке времени, мок-backend) — без «coordinated
  omission», в духе `tools/mc-bench` из Infrarust (идея).

## Non-goals

- Постоянная трассировка в проде; GUI.

## Критерии приёмки

- [ ] `explain` не меняет ни один счётчик (тест до/после).
- [ ] Стоимость программы воспроизводима (разброс < 10 %) и пишется в датированный JSON.

## Верификация

Сверка вердикта `explain` с реальным поведением в netns-стенде.
