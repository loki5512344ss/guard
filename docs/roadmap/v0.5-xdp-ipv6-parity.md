# v0.5 — XDP: IPv6-паритет для L4

| | |
|---|---|
| Milestone | v0.5 |
| Status | idea |
| Priority | P1 |
| Depends on | v0.4-xdp-ci-harness |

## Цель

Защита L3/L4 на IPv6 такая же, как на IPv4: SYN-флуд по v6 режется в XDP, а не доходит до
userspace.

## Зачем

По `docs/architecture.md` §3.1 на IPv6 в XDP работают только blacklist/whitelist, UDP-policy
и prefix-статистика. TCP conntrack, SYN-throttle и ringbuf-события — только IPv4 (для v6
есть счётчики без событий, значит и auto-ban по v6-флуду не сработает). Атакующему
достаточно перейти на IPv6. RST-challenge для v6 покрыт отдельной задачей
[v0.5-rst-challenge-ga.md](v0.5-rst-challenge-ga.md), здесь — остальное.

## Scope

- `throttle_hit6` и TCP conntrack для IPv6 (128-битные ключи; проверить размеры карт и
  лимиты verifier на ядрах 5.15 и новее).
- Ringbuf-события для IPv6 и поддержка в `parse_xdp_event` / auto-ban по v6-источнику
  (бан /128 и префикса /64).
- Паритетная матрица в `docs/architecture.md`; метрики по семействам адресов.

## Non-goals

- ICMPv6/NDP-политики; изменение формата IPv4-карт.

## Approach

1. Аудит `universal_filter.c`: где v6-ветка выходит раньше IPv4.
2. Ключи и карты v6 с тестом ABI (по образцу `tests/xdp_ban_keys.rs`, `xdp_ban_v6.rs`).
3. Расширить `xdp_ipv6_smoke.sh` (сначала починить, см. v0.5-xdp-hardening-followups) и
   `xdp_stress.sh` режимом IPv6.

## Критерии приёмки

- [ ] SYN-флуд по IPv6 в стенде дропается в XDP; метрики растут.
- [ ] Событие v6 доходит до userspace, auto-ban банит источник.
- [ ] Verifier принимает программу на 5.15 и на новом ядре (`xdp_ci.sh`).
- [ ] Матрица в architecture.md без строк «нет» для перечисленных механизмов.

## Верификация

`xdp_ci.sh --with-ipv6` и стресс-прогон с v6-источниками на KVM-ноде.
