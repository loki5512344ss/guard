## Цель

RST-challenge (Oubliette-style liveness proof) работает для IPv4 и IPv6, включён
документированным способом и заменяет текстовый PoW там, где PoW несовместим с
протоколом.

## Зачем

В коде уже есть `xdp/core/syn_challenge.h` и `[xdp] syn_challenge_enabled`
(IPv4, SYN-ACK с неверным ACK → RST от живого клиента → verified). Это
универсальная проверка liveness, совместимая с любым TCP-клиентом, в отличие от
userspace PoW, который ломает протоколы с собственным handshake (Minecraft).
Осталось довести до продакшена и убрать расхождение «фича есть в C, но не в
документации/дефолтах».

## Известный пробел (найден стресс-прогоном v0.4) — исправлен

`SOURCES=random bash scripts/xdp_stress.sh` давал `challenge_verified = 0`: живой клиент
не проходил challenge даже без флуда. Причин было две:

1. **Баг challenge.** Ack в SYN-ACK брался из всего 32-битного пространства. Conntrack
   клиента (`ufw`, NAT-роутер) помечает такой SYN-ACK как INVALID и дропает до TCP-стека.
   Теперь ack = `ISS+1−k`, `1 ≤ k ≤ 2^15`: внутри окна conntrack, но `SEG.ACK ≤ ISS` →
   RST. Проверено на VDS за `ufw` (`ct state invalid drop`): клиент проходит за ~15 мс.
2. **Стенд.** `XDP_TX` на veth доходит до пира только при native XDP-программе на пире;
   скрипты вешают pass-программу.

Регрессия закрыта фазой `chal` в `scripts/xdp_challenge_test.sh` (на старом коде падает).

## Scope

- IPv6-паритет: 128-битные flow-ключи для pending-challenge и verified-состояния.
- Метрики: выданные challenge, прошедшие/просроченные, доля verified-источников.
- Заменить/дополнить PoW: описать матрицу «протокол → PoW / RST-challenge / оба»,
  обновить `[pow]` и `[xdp]` в configuration.md.
- Интеграционные тесты: живой клиент проходит, спуф не проходит; TTL challenge.
- Docs: отдельный раздел про challenge в architecture.md и runbook.

## Non-goals

- RST-challenge для UDP.
- Хранение verified-состояния в Redis между нодами (сейчас локально в XDP).

## Approach

1. Аудит текущего C-кода и ABI: ключи, таймауты, взаимодействие с conntrack.
2. v6: расширить `flow_key` или добавить `flow_key6`; проверить размер карт.
3. Userspace: метрики и переключатель; логировать причину отказа без секретов.
4. Тесты: `tests/xdp_ban_keys.rs` рядом, `scripts/xdp_ci.sh` из v0.4.
5. Документация и дефолты: решение «включать по умолчанию» принимается только
   после нагрузочного стенда.
