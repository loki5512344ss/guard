# v0.6 — BGP Anycast

| | |
|---|---|
| Milestone | v0.6 |
| Status | idea |
| Priority | P3 |
| Depends on | несколько edge-площадок |

## Цель

Анонс защищаемого префикса (`/24` + AS) с нескольких edge-площадок, чтобы
атакующий трафик распределялся, а клиент попадал на ближайшую ноду.

## Зачем

Это инфраструктурный уровень защиты, который сейчас закрывают только провайдеры.
Для одиночного VDS не нужен, но без него нельзя называться «платформой».

## Non-goals

- Собственная BGP-реализация с нуля: используем зрелый демон (BIRD/FRR) и
  управляем им.
- Автоматический анонс при атаке без оператора.

## Approach

1. Исследовать: BIRD/FRR + health-check, при котором withdraw происходит при
   деградации ноды.
2. Написать интеграцию (генерация конфига, health-скрипт), а не демон.
3. Лабораторный стенд: два netns с BGP-сессией, проверка withdraw/failover.

## Критерии приёмки

- [ ] Failover проверен в лаборатории, время withdraw задокументировано.
- [ ] Конфиг генерируется из одного источника (manager inventory).
- [ ] Есть runbook на случай анонса «плохого» префикса.
