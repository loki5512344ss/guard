## Цель

Edge работает с минимальным набором прав, а не от root: XDP загружается и аттачится,
остальное — без привилегий.

## Зачем

Сейчас edge ожидает root (диагностика v0.4 уже различает права по `CapEff`:
`CAP_NET_ADMIN` + `CAP_BPF` + `CAP_PERFMON`). Компрометация демона с root — максимальный
ущерб. ebpfsentinel запускает агент под отдельным «warden» через BPF token и systemd-юнитом
с ограниченными capabilities (идея; код AGPL — не копируем).

## Scope

- systemd-юнит и Docker-профиль с `AmbientCapabilities`/`--cap-add` вместо root; тест, что
  edge стартует и XDP аттачится под этими правами (в netns, `xdp_ci.sh`).
- Исследовать BPF token (ядро ≥ 6.9): стоит ли разделять «загрузчик» и «рабочий» процесс.
- Раздел в `deployment.md`/`runbook.md`; hint диагностики указывает готовый юнит.

- Готовые артефакты усиления (couic — Apache-2.0, ebpfsentinel — идея): systemd-директивы
  `ProtectSystem=strict`, `SystemCallFilter`, `MemoryDenyWriteExecute`,
  `RestrictAddressFamilies`, `RuntimeDirectory`; seccomp/AppArmor-профили и sysctl-снимки в
  `deploy/`. Это дешёвая часть — брать первой.
- Сброс capabilities и смена пользователя после attach (демон держит права только на время
  загрузки); привилегированный брокер с узким протоколом — отдельным поздним шагом.

## Non-goals

- Seccomp/AppArmor-профили (отдельно, если понадобится).

## Критерии приёмки

- [ ] Edge под непривилегированным пользователем с тремя capabilities проходит `xdp_ci.sh`.
- [ ] Без `CAP_BPF` — внятный отказ с hint (уже есть), с ними — работа.
- [ ] Юнит/профиль в `deploy/` и описание в docs.

## Верификация

Прогон smoke от пользователя `rampart` с ambient capabilities на KVM-ноде.
