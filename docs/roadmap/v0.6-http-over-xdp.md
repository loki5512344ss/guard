# v0.6 — HTTP поверх XDP (BPF hook)

| | |
|---|---|
| Milestone | v0.6 |
| Status | idea |
| Priority | P1 |
| Depends on | v0.4-xdp-ci-harness, v0.5-rst-challenge-ga |

## Цель

Первый реальный BPF-протокол-хук: разбор начала HTTP-запроса в XDP и rate-limit
по L7-признакам до того, как соединение дойдёт до userspace.

## Зачем

Сейчас `xdp/hooks/hook_api.h` — контракт без потребителя, а HTTP-фильтрация
происходит только в userspace: под флудом соединений CPU тратится на accept и
чтение заголовков. Хук в ядре снимет основную часть нагрузки на дорогие атаки.

## Scope

- Ограниченный парсер: метод, путь, Host, User-Agent — с жёсткими лимитами.
- Tail-call цепочка из основной программы в hook (без роста сложности
  `universal_filter.c`).
- Политика: drop/rate-limit по пути и User-Agent; конфиг в `.rodata`.
- Тесты в netns-стенде + fuzz-цель на тех же байтах, что и userspace-парсер.

## Non-goals

- Полный HTTP-парсер в BPF (TLS, body, chunked).
- Замена userspace HTTP-плагина: хук — быстрый предфильтр, финальное решение
  остаётся за `ProtocolHandler`.

## Approach

1. Прототип отдельной BPF-программы с `test_run` на сохранённых пакетах.
2. Сравнить pps/CPU с текущим userspace-путём на `deploy/test/stress/`.
3. Только при выигрыше — интегрировать в загрузчик и конфиг.

## Критерии приёмки

- [ ] Хук не меняет вердикты userspace-фильтра (property-тесты на одних байтах).
- [ ] Бенчмарк показывает измеримый выигрыш на HTTP-flood.
- [ ] Верификатор проходит на kernel ≥ 5.10, размер программы в лимитах.
- [ ] Фича выключена по умолчанию и не ломает сборку без неё.
