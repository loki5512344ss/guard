## Цель

Edge при старте сам говорит, что с окружением: kernel, BTF, драйвер NIC,
поддержка native/generic XDP, доступные capabilities — и падает с внятной
причиной, если XDP включён, но загрузиться не сможет.

## Зачем

Диагностика уже есть в `rampart-cli doctor` (`src/xdp/probe/`, `EnvironmentReport`),
но демон её не использует. У конкурентов ~80% issues про XDP — это attach на
неподдерживаемом окружении (OpenVZ/LXC, старый kernel, отсутствие BTF), при этом
сообщение появляется уже после неудачного `load()`.

## Scope

- Переиспользовать `EnvironmentReport`/`FilesystemProbe` при старте edge, а не
  писать второй детектор.
- Один структурированный лог-вердикт: `kernel`, `virt`, `interface`, `driver`,
  `native|generic|none`, причина отказа.
- Fail-fast только когда `[xdp] enabled = true` и загрузка невозможна; иначе —
  предупреждение и работа без XDP (текущее поведение сохраняется).
- Код возврата/сообщение для systemd: человек читает `journalctl` и понимает, что
  делать, без чтения исходников.

## Non-goals

- Автоматическое лечение окружения (загрузка модулей, смена драйвера).
- Полноценный `doctor` в демоне: интерактивные проверки остаются в CLI.

## Approach

1. Вынести общий «вердикт» в `src/xdp/probe/`, чтобы CLI и демон печатали одно и
   то же.
2. В `app::runtime` перед `start_xdp` логировать отчёт; при ошибке attach —
   приложить вердикт к ошибке.
3. Тесты: чистая функция форматирования отчёта (без root), плюс существующие
   `tests/xdp_diagnostics.rs`.
4. Документация: раздел в `docs/troubleshooting.md` и `docs/runbook.md` со
   ссылкой на тот же вердикт.

## Критерии приёмки

- [x] На kernel без BTF/в LXC лог содержит причину и рекомендацию. (unit-тесты на mock-probe; живой LXC не проверялся, контейнер docker без CAP_BPF — проверен на KVM-ноде)
- [x] В KVM с virtio вывод честно говорит `generic (skb)`, а не «XDP works». (`expected_mode` — предсказание по таблице драйверов, реальный режим логируется после attach из ядра)
- [x] `rampart-cli doctor` и edge используют один код формирования отчёта (`EnvironmentReport::summary_fields`).
- [x] `cargo clippy --all-targets --all-features -- -D warnings` чистый.

## Верификация

Прогон в двух окружениях: обычный хост и контейнер без `CAP_BPF`; вывод
сравнивается с `docs/troubleshooting.md`.
