## Цель

Установка одной командой и воспроизводимый релиз: deb/rpm, systemd-юнит, man-страницы,
идемпотентный workflow.

## Зачем

Сейчас бинарь и образ собираются в CI, но пакетов и процесса релиза нет. Идеи из couic
(Apache-2.0: cargo-deb/cargo-generate-rpm, man из clap, pinned actions) и
Minecraft-XDP-eBPF (BSD-3: release по push в main с проверкой существующего тега).

## Scope

- `cargo-deb` и `cargo-generate-rpm`; unit, postinst/postrm; cross-сборка arm64 (по спросу).
- Man-страницы и completions из `clap` (`rampart-cli`).
- Release workflow: тесты → сборка → проверка, что тег не существует → `gh release` с
  бинарями и BPF `.o`; сборка до bump версии, чтобы вшитая версия была верной; сериализация
  через concurrency.
- Все GitHub Actions закреплены по SHA с комментарием версии; dependabot для обновлений.
- Установка `bpf-linker`/инструментов через `cargo binstall` там, где это ускоряет CI.

## Non-goals

- Отдельный сайт документации (достаточно `docs/`); репозиторий apt/yum.

## Критерии приёмки

- [ ] `.deb` ставится на чистую Ubuntu 22.04/24.04, юнит стартует, `rampart-cli --help` есть
  в man.
- [ ] Повторный запуск release workflow не создаёт дубль тега.
- [ ] Все `uses:` в `.github/workflows` с SHA.

## Верификация

Установка пакета в чистой VM и проверка `xdp_ci.sh` против установленного бинаря.
