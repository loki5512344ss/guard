# v0.6 — io_uring runtime

| | |
|---|---|
| Milestone | v0.6 |
| Status | idea |
| Priority | P3 |
| Depends on | бенчмарк relay-пути |

## Цель

Опциональный io_uring-транспорт для relay: меньше syscall и копий на горячем
пути пересылки.

## Зачем

Фича `io-uring` и зависимость `tokio-splice` объявлены, но не используются. На
relay-пути доминируют `read`/`write` и копии; `splice`/io_uring могут снизить CPU
на высоких pps.

## Non-goals

- Замена tokio целиком: только транспорт relay-соединений.
- Требование io_uring для работы edge: feature опционален, дефолт — текущий путь.

## Approach

1. Замерить текущий relay: `perf`/`samply` на нагрузочном стенде, найти долю
   syscall.
2. Прототип `RelayTransport` на `tokio-splice`, сравнить на 1/10/100k соединений.
3. Оставить фичу только если выигрыш воспроизводим и код не разрастается.

## Критерии приёмки

- [ ] Замеры до/после с методологией в `docs/research/benchmark.md`.
- [ ] `--features io-uring` собирается и тестируется в CI.
- [ ] Поведение при недоступном io_uring — прозрачный fallback.
