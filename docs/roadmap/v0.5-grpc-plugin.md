# v0.5 — gRPC protocol plugin

| | |
|---|---|
| Milestone | v0.5 |
| Status | idea |
| Priority | P2 |
| Depends on | стабильный `ProtocolHandler` API |

## Цель

Плагин, который понимает gRPC поверх HTTP/2: валидирует префикс запроса, умеет
отклонять мусор до upstream, поддерживает multiplexing без потери соединений.

## Зачем

После HTTP/1.1 логичный следующий протокол: gRPC — стандарт для внутренних API, а
его handshake (HTTP/2 preface + SETTINGS) дешёво проверяется в userspace. Даёт
кейс «защитить внутренний сервис», а не только публичный сайт.

## Scope

- Разбор HTTP/2 preface и первых фреймов (SETTINGS/HEADERS) с лимитами.
- Решение Allow/Reject и туннелирование на upstream без буферизации всего потока.
- Конфиг `[protocol.grpc]`: лимиты заголовков, таймауты, разрешённые пути.
- Тесты на фрагментацию (парсер обязан переживать «один read»).

## Non-goals

- Полноценный HTTP/2-прокси с приоритетами и flow control.
- gRPC-рефлексия и десериализация сообщений.

## Approach

1. Переиспользовать HTTP/1.1-парсер там, где применимо; HTTP/2 preface —
   отдельная маленькая стейт-машина.
2. Новый feature `protocol-grpc`, регистрация в `ProtocolRegistry`.
3. Fuzz-цель `http2_preface` рядом с существующими.
4. Документация: `docs/configuration.md` + отдельный пример конфига.

## Критерии приёмки

- [ ] `--features protocol-grpc` собирается и покрыт тестами в CI.
- [ ] Парсер не выходит за буфер на произвольных байтах (fuzz 60 с в `make fuzz`).
- [ ] Нет регрессии латентности HTTP/1.1-пути (bench hot_paths).
