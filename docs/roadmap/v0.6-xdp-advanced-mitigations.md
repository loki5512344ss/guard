# v0.6 — XDP: продвинутые меры (исследование)

## Цель

Выбрать, какие приёмы ядерной защиты дают измеримый выигрыш поверх RST-challenge; каждый
начинается с прототипа и замера.

## Кандидаты

- **SYN cookies из XDP** (ebpfsentinel, идея; `bpf_tcp_raw_gen_syncookie`/check, ядро ≥ 5.10,
  `tcp_syncookies=1`): ответить SYN-ACK с cookie без состояния; спуф не аллоцирует
  ничего. Только IPv4, verifier-тяжело; дополняет, а не заменяет RST-challenge.
- **Не отвечать на голый ACK рукопожатия** (Minecraft-XDP-eBPF): ядро завершит соединение
  по первому проверенному пакету данных; спуф и простаивающие соединения не попадают в accept.
- **`bpf_timer`** (ядро ≥ 5.15, GPL-совместимая лицензия программы): самоочистка окон
  throttle и conntrack вместо userspace-reaper (для банов оставить reaper — см. LPM).
- **bps-лимиты и ключ потока** (XDP-Firewall): `{pps,bps}` на IP и на (ip, sport, proto) ловят
  UDP-флуд крупными пакетами и позволяют душить один поток без бана адреса.
- **Точная проверка фрейма Minecraft в XDP** (Minecraft-XDP-eBPF): длина = потреблённым
  байтам, caps на hostname/username, ограниченный varint (`barrier_var`, развёрнутые шаги);
  общий приём для [v0.6-http-over-xdp.md](v0.6-http-over-xdp.md).
- **Операторские правила** (узкая версия): гейты по длине/TTL для UDP, ICMP type/code.

## Non-goals

- Линейный список правил с `bpf_loop` в горячем пути (авторы XDP-Firewall признают, что не
  масштабируется).

## Критерии приёмки

- [ ] По каждому кандидату — прототип и замер на стенде (`xdp_stress.sh`, стоимость
  программы), иначе `dropped` с причиной.
- [ ] Принятое проходит `xdp_ci.sh` на 5.15 и ≥ 6.x и не ломает IPv6-паритет.

## Верификация

Сравнение drop-ratio, CPU и задержки легитимного клиента до/после на одном железе.
