## Цель

Минимальные проверки, доступные прокси без расшифровки: плохие клиенты отсекаются до
upstream, а оператор видит причины отказов.

## Зачем

Rampart — прозрачный прокси и не читает зашифрованный трафик, но handshake и login-start
идут открытым текстом. Разбор sonar (GPL — только идеи) и Infrarust (AGPL — только идеи)
показал дешёвые проверки; реальное покрытие нашего `src/protocol/minecraft/` нужно сверить.

## Scope

- Конечный автомат handshake→login: пустой hostname, второй handshake, второй login-start,
  login до handshake, неизвестный protocol id → тихий дроп; username по regex/длине.
- Лимиты размера кадра по фазе до буферизации (около 2 КиБ handshake, 5 КиБ login-start,
  64 байта status request); handshake декодируется независимо от версии протокола.
- Таблица версий протокола `(id → имя)`; конфигурируемые min/max и deny-список; метрика по
  версиям с ограниченной кардинальностью.
- Метрики: `rampart_mc_handshake_total{result,reason}` (reason — закрытый enum), логины/с как
  отдельный сигнал от cps.
- Лимиты, учитывающие login: считать только соединения, дошедшие до login-start, и число
  разных username с одного IP за окно; отдельный бюджет для status-ping (ключ — IPv4 или
  IPv6 `/64`).
- Fail-score по IP с затуханием (интеграция с `IpReputation`/`TrafficHook`): аномалии
  handshake — события с весами, порог → `ban`/`ban_cidr`.
- Проверки «только под атакой» (тайминг NEVER/DURING_ATTACK/ALWAYS по состоянию
  `AttackDetector`); сводка по атаке в webhook.
- Status: single-flight на upstream и негативный кэш на несколько секунд (флуд ping в
  мёртвый backend не открывает соединение на каждый ping) — дополняет кэш из
  [v0.6-hot-path-perf.md](v0.6-hot-path-perf.md).

## Non-goals

- Проверки гравитации/коллизий/капча (нужен фейковый сервер); brand-проверки (зашифровано
  в online-mode); обработка Geyser/Eaglercraft.

## Критерии приёмки

- [x] Каждый вид аномалии покрыт тестом (порядок пакетов, размеры, версии, username): `tests/protocol_minecraft_state.rs`, `tests/protocol_minecraft_handler.rs`.
- [x] Метрики видны в `/metrics` с закрытым набором label (`rampart_mc_handshake_total`, `rampart_mc_protocol_version_total`).
- [ ] Строгие проверки под атакой включаются автоматически и логируются.
- [ ] Валидный клиент не затронут (e2e-тест через `tests/edge_e2e`).

## Верификация

e2e с набором «плохих» клиентов (скрипт на сыром TCP) и стресс-прогон под флудом ping.

## Прогресс

Сделано (часть 1): конечный автомат handshake→status/login, лимиты кадра по фазе до
буферизации, таблица версий + min/max/deny, username-валидация, метрики
`rampart_mc_handshake_total` / `rampart_mc_protocol_version_total`.

Не сделано (остаётся открытым): логины/с как отдельный сигнал, лимиты по login-start и
числу username с IP, бюджет status-ping, fail-score по IP, проверки «только под атакой»
(третий и четвёртый пункты приёмки), single-flight и негативный кэш status, e2e через
`tests/edge_e2e` (он собирается только с `protocol-http`; пока покрыто loopback-тестом
handler'а), обнаружение второго login-start после ответа сервера (нужен инспектор в relay).
