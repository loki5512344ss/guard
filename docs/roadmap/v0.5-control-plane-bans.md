# v0.5 — Управление банами: теги, наборы, API и CLI

## Цель

Видно, кто и почему банит; внешние списки подключаются атомарно; CLI и API удобны и
безопасны для интеграций.

## Зачем

Идеи из couic (Apache-2.0) и ebpfsentinel (AGPL — только идеи). Сейчас баны не
различаются по источнику (детектор, ручной, Redis, GeoIP), внешние списки (тема v0.5) негде
хранить отдельно от ручных банов, а API защищён одним паролем с JWT.

## Scope

- **Теги банов** (источник/детектор) и счётчики дропов по тегу в Prometheus.
- **Именованные наборы** (импортированные списки: ASN, abuse-фиды): заменяются атомарно и
  удаляются, не трогая ручные баны.
- **Batch-обновление карт** (`BPF_MAP_UPDATE_BATCH`, ядро 5.6+) порциями с откатом на
  поэлементную запись; важно для больших фидов и GeoIP.
- **Сроки:** человекочитаемые длительности в CLI (`30s`, `1h30m`, голое число отвергается),
  абсолютный `expires_at` в API; строгая валидация ввода CLI/API (хвост после порта, `/0`,
  перевёрнутые диапазоны).
- **Доступ:** локальный admin-сокет для CLI без JWT и scoped-токены для интеграций
  (read-only для Grafana, ban-only для детекторов).
- **Персистентность:** авторитетное хранилище — userspace/Redis, pinned maps — лишь
  представление (так делает couic); учесть в [v0.5-pinned-maps-openapi.md](v0.5-pinned-maps-openapi.md).
- **API-тесты** HTTP-контрактов (hurl-файлы) рядом с OpenAPI conformance-тестом.

## Non-goals

- Вторая схема синхронизации узлов (есть Redis); полный RBAC с ролями-ресурсами.

## Критерии приёмки

- [ ] Дропы по тегам видны в метриках; тег виден в `list`.
- [ ] Замена набора не затрагивает баны других источников (тест).
- [ ] `rampart-cli ban --for 1h30m` работает; `--for 90` отвергается с подсказкой.
- [ ] Scoped-токен read-only не может создать бан (тест).

## Верификация

Интеграционный прогон manager API + загрузка набора на 100k записей с замером времени.
