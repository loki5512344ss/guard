## 7. Как вести документацию

1. **Язык.** `docs/` — русский. Исключение: [docs/kb/](kb/README.md), где статьи
   двуязычные (`## English` / `## Русский`). Комментарии в коде — английский
   ([development.md](development.md) §5).
2. **Один документ = одна задача.** How-to начинается с цели («что получится в
   конце»), содержит копируемые команды и заканчивается проверкой результата.
3. **Reference синхронизируется с кодом в том же PR.** Меняешь поле конфига, флаг
   CLI или эндпоинт — правишь `configuration.md` / `api.md` там же. Расхождение =
   баг.
4. **Планы не растут в TODO.** Новая задача — новый файл в
   [roadmap/](roadmap/README.md); в `TODO.md` добавляется только строка-ссылка.
5. **Новый документ** кладётся в подходящую категорию (1–6) и сразу добавляется в
   эту таблицу; если он является точкой входа — ссылка добавляется и в корневой
   README.
6. **Не размножай папки.** Плоская структура `docs/*.md` — норма; подпапка нужна
   только для серии документов (`kb/`, `research/`, `roadmap/`).
7. **Имена файлов** — kebab-case, `.md`, без дат в имени; дата и версия — внутри
   документа.
8. **Никаких битых ссылок.** Перед коммитом: `bash scripts/check_docs_links.sh`
   (этот же скрипт работает в CI).
9. **Не дублируй архитектуру.** Схемы и описания слоёв живут в
   [architecture.md](architecture.md); остальные документы ссылаются на него.
